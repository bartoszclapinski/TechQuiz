# Iteration 4.11 — Demo hardening

## Goal
Make the live portfolio demo self-explanatory and safe to leave open:
1. **Seed the shared demo account with a realistic quiz history** so the Dashboard, History,
   Categories progress and Result screens have content on first visit (no empty states).
2. **Close public registration** until there's a privacy policy / GDPR story, so nobody creates
   an account whose data we can't yet handle. Login + the demo account stay open.

## Decisions (owner)
- **Demo freshness: always refresh on boot.** The seeder wipes the demo user's attempts and
  regenerates them with dates relative to now on every startup — the demo never goes stale, and the
  shared account self-cleans whatever a previous visitor did. Only the demo user is touched.
- **Registration: endpoint + UI.** A config flag gates the API endpoint (403 when off) *and* the UI
  is hidden — not just cosmetic. Reversible via config when a privacy policy exists.

## Delivery — one PR per slice
1. **Demo history seed** — `DataSeeder.SeedDemoHistoryAsync`: ~19 completed attempts across 8
   categories over the last ~14 days, a ~12-day streak, gently rising scores; refreshed each boot.
   ← *this PR*
2. **Close registration** — `Auth:RegistrationEnabled` flag (default false) → `RegisterCommand`
   throws / endpoint 403; web hides the register route + "Create one" links + demo-only note.

## Definition of Done
- [ ] Demo account shows a populated Dashboard/History/Categories/Result on the live site.
- [ ] Registration endpoint returns 403 when the flag is off; register UI is gone; login + demo work.
- [ ] Backend tests green (seed refresh, registration gate); web build/lint green.
- [ ] Owner confirms on the live site.
