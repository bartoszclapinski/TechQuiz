# Iteration 4.9 — Desktop readability / typography scale

> Phase 4 · Status: in-progress

## Goal
The app was built mobile-first with a very compact type scale — ~250 hardcoded pixel sizes
(`text-[10px]` ×38, `text-[11px]` ×41, `text-[13px]` ×66, plus `text-xs`/`text-sm`). On desktop the
text reads as tiny and hard to scan (owner-reported on the live dashboard). There is no central lever,
so this iteration bumps the whole scale up one coherent step, preserving hierarchy.

Pure styling — no logic, API, or layout-structure changes.

## Type-scale bump (owner-approved "moderate")
Applied app-wide (all breakpoints), largest-source-first so nothing double-bumps:

| Before | After | Role |
|---|---|---|
| `text-[9px]`  | `text-[11px]` | micro |
| `text-[10px]` | `text-[12px]` | mono labels |
| `text-[11px]` | `text-[13px]` | badges/pills |
| `text-[12px]` / `text-xs` | `text-[13px]` | secondary |
| `text-[13px]` | `text-[14px]` | body copy |
| `text-[14px]` / `text-sm` | `text-[15px]` | base |
| `text-[15px]` | `text-[16px]` | emphasized body |
| `text-base` and true headings (≥17px, `text-2xl`, `text-[28px]`, …) | unchanged | display |

## Definition of Done
- [ ] Scale bump applied across `web/src`; no size tier collapses out of order.
- [ ] `pnpm build` + `pnpm lint` clean.
- [ ] Key screens sanity-checked (dashboard, categories, quiz, result, history, login) — no clipped/broken layout.
- [ ] Live: dashboard + category descriptions read comfortably on desktop; owner-confirmed.
