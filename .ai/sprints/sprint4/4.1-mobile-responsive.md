# Iteration 4.1 — Mobile responsive

> Phase 4 · Status: done

## Goal
Make every screen usable on a phone (**375–768px**) without horizontal overflow, cramped chrome, or
unreachable actions. Today the app is desktop-first: the topbar packs a logo + **seven** nav links +
settings/theme/avatar on one row (overflows well before 768px), the Dashboard bento grid and the
code-challenge editor assume wide viewports, and several primary tap targets are below a comfortable
finger size. This iteration:
- collapses the topbar nav into a **hamburger drawer** below `md`, keeping the desktop bar unchanged
  above it,
- makes the content screens **reflow to a single column** with sensible ordering and chart/tile sizing,
- grows primary **tap targets** (quiz/review options, main buttons) to a comfortable minimum,
- keeps the focused runner screens (`/quiz/:id`, `/review/run`) chrome-less as they are (ADR-014).

Pure frontend — **no backend, API, or contract changes**. No mockups exist for Phase 4 (the README
defers them); we design responsively with the existing design tokens and Tailwind breakpoints.

## Scope
- **In:**
  - **Responsive nav shell (`AppShell`):**
    - Extract the seven nav items into a single shared list (one source of truth) rendered two ways:
      the existing horizontal bar at `md+`, and a **hamburger button → slide-in drawer** below `md`.
    - Drawer: opens from the hamburger, lists the nav links (larger, stacked, ≥44px rows) plus
      settings + theme + logout, closes on link-tap / backdrop-tap / route change, traps nothing fancy
      (a full a11y focus-trap pass is 4.4). Body scroll locked while open.
    - The focused runner routes still render just the `<Outlet />` (unchanged rule).
  - **Content reflow (base = mobile, layer up with `sm:`/`lg:`):**
    - **Dashboard** — already partly responsive; verify it collapses cleanly to one column at 375px,
      tighten page padding (`px-6` → smaller on mobile), ensure Recharts containers and the review tile
      don't overflow, reorder so the most useful tiles lead on mobile.
    - **Categories / Pool / History / Challenges list** — grid/list to single column, readable rows.
    - **Quiz runner + Review runner** — options become full-width, ≥44px tap targets; progress/header
      fit narrow widths; sticky action button reachable with a thumb.
    - **Result / Review session detail** — score header + per-question breakdown stack; no clipped rows.
    - **Generate / Settings** — forms go single-column, inputs full-width, labels above fields.
    - **Login / Register** — center card fits 375px with comfortable padding.
    - **Code challenge editor** — the hardest: on narrow screens **stack** the Monaco editor above the
      test/verdict panel instead of side-by-side; ensure Run/Submit stay reachable. Editor stays
      desktop-first in spirit (not a full mobile IDE) but must be usable — see decision (d).
  - **Tap targets** — primary interactive elements (quiz/review options, primary buttons, drawer rows)
    meet a ~44px minimum height.
- **Decisions:**
  - **(a) Mobile-first, Tailwind breakpoints.** Base styles target the phone; `sm:`/`md:`/`lg:` layer
    the wider layouts on top. This matches the codebase's existing `sm:`-prefixed usage and avoids a
    parallel set of desktop overrides.
  - **(b) `md` (768px) is the nav breakpoint.** Below it, hamburger; at/above, the current bar. One
    shared nav-item list feeds both, so links never drift out of sync.
  - **(c) No backend / API / route changes.** Same routes, same components where possible — this is
    layout and CSS, not new features. Feature folders keep their pages; the shell and per-screen classes
    change.
  - **(d) The code editor is stacked, not reinvented, on mobile.** A true touch coding experience is out
    of scope; the goal is "a reviewer on a phone can read the prompt, see the code, and run it," so we
    stack panels and keep actions reachable rather than build mobile-specific editor UX.
  - **(e) No component tests.** Per the MVP testing rule frontend has no test mandate; 4.1 is verified by
    build + lint + manual click-through at mobile widths. (Vitest component tests remain a later option.)
  - **(f) Achievements gallery / toasts (planned 4.3) stay out.** 2.9 already shipped the achievements
    section; 4.1 only ensures it reflows. The 4.3 overlap is noted for later reconciliation.
- **Out:**
  - Gamification XP/levels (4.2) and the achievements gallery/toasts (4.3).
  - Accessibility audit / full focus-trap / screen-reader pass (4.4).
  - Performance / bundle-splitting / Lighthouse (4.5).
  - Landscape-phone and tablet-specific tuning beyond "doesn't break" (portrait 375–768 is the target).
  - Any redesign of the visual language — this is reflow, not restyle.

## Definition of Done
- [x] Topbar collapses to a hamburger drawer below `md`; drawer opens/closes (button, backdrop, route
      change), every nav link + settings/theme/logout reachable; body scroll locked while open. Both themes.
- [x] At **375px** every authenticated route renders with **no horizontal overflow**: dashboard, history,
      review hub/runner/detail, categories, generate, pool, challenges list + editor, settings, quiz,
      result. Login + register too.
- [x] Dashboard reflows to a single column with charts/tiles sized to the viewport (no clipped Recharts).
- [x] Quiz + review options and primary buttons have ≥~44px tap targets.
- [x] Code-challenge editor stacks (editor over test panel) on narrow screens with Run/Submit reachable.
- [x] Focused runner screens (`/quiz/:id`, `/review/run`) remain chrome-less.
- [x] `pnpm build` + lint clean.
- [x] Manual verification in `LOG.md`: stack up, walk every screen at 375 / 414 / 768px in both themes;
      hamburger drawer works; no overflow. Owner click-through confirms.
