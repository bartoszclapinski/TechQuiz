# Iteration 3.5 — Public pool (persistence + attribution + browse)

> Phase 3 · Status: in-progress

## Goal
Make generated questions durable. Today `POST /api/ai/questions` returns drafts and throws them
away (3.4). This iteration persists each generated draft as a `PooledQuestion` with attribution
(generating user, provider, timestamp) and the server-side correct option, then lets the author
**publish** a draft into the shared public pool and lets any user **browse** the published pool.

This delivers the first vertical slice of ADR-007's public pool, using the Draft → Published
lifecycle decided in ADR-020.

## Scope (decided with owner — Option B / ADR-020)
- **In:**
  - `PooledQuestion` Domain aggregate (TDD): content + options (one correct, server-side) +
    attribution (UserId, provider, GeneratedAtUtc) + `Status` (Draft/Published) + `Publish()`.
  - Generation persists drafts as `Draft` (changes `POST /api/ai/questions` to write — ADR-020).
  - Application (TDD): publish a draft; list published pool questions (answer key omitted).
  - Infrastructure: repository + EF mapping + migration.
  - API: publish + list-pool endpoints.
  - Frontend: enable "Save to my pool" (= publish) on the generate preview; a simple pool browse view.
- **Deferred (ADR-007, Phase 3/4):** voting, flagging, moderation queue, and **playing** pooled
  questions as quizzes (no topic→category mapping, no quiz-runner wiring in 3.5).

## Key constraint — the correct answer never leaves the server
`CorrectOptionIndex` is held server-side from generation onward and stored on the aggregate. It is
**never** serialized to any client in either `Draft` or `Published` state (hard rule #4). Because the
client never receives it, the publish action references a **server-held draft by id** — the client
does not (and cannot) round-trip the answer key.

## Contract (new in 3.5)
- `POST /api/ai/questions` — **now persists** each draft as a `Draft` `PooledQuestion` owned by the
  caller, in addition to returning the (answer-key-free) preview. Response shape unchanged from 3.4,
  but each returned draft now carries its server-side `id` so the UI can publish it.
- `POST /api/pool/questions/{id}/publish` — transitions the caller's own `Draft` to `Published`.
  `401` unauthenticated, `403`/`404` if the draft isn't the caller's, `409` if already published.
- `GET /api/pool/questions` — lists `Published` pool questions (stem, options, difficulty,
  explanation, provider, author attribution, timestamp). **No answer key.**
- Difficulty/provider stay enum **names** on the wire, consistent with the rest of the AI feature.
