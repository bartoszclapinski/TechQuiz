# Iteration 1.2 — Application layer (MediatR + TDD)

> Phase 1 · Status: done

## Goal
All MVP use cases exist as MediatR commands/queries with handlers, validators, and DTOs. Application layer depends on Domain + abstractions only — no Infrastructure references.

## Definition of Done
- [x] MediatR registered in DI, pipeline behaviors for validation + logging
- [x] FluentValidation registered for all commands
- [x] Application interfaces defined: `IQuizRepository`, `ICategoryRepository`, `IUserContext`, `IUnitOfWork`
- [x] DTOs defined for all read/write operations (no Domain entities crossing the boundary)
- [x] MVP use cases implemented as handlers (list below)
- [x] `dotnet test TechQuiz.Application.Tests` passes with 40+ tests (actual: 46)
- [x] No reference to `Microsoft.EntityFrameworkCore` or `Npgsql` in Application project

## MVP use cases
- `GetCategoriesQuery` → list of categories with question count + user progress percentage
- `StartQuizCommand` → returns QuizAttemptId + ordered questions (without correct answers exposed)
- `SubmitAnswerCommand` → records an answer for an attempt
- `CompleteQuizCommand` → finalizes attempt, computes score, returns ResultDto
- `GetAttemptHistoryQuery` → list of past attempts for a user (used in Phase 2 too)

## Tasks (in order)

1. **Install MediatR + FluentValidation** — `MediatR`, `MediatR.Extensions.Microsoft.DependencyInjection`, `FluentValidation`, `FluentValidation.DependencyInjectionExtensions`. Register in `Application/DependencyInjection.cs`
2. **Pipeline behaviors** — `ValidationBehavior<TRequest, TResponse>` runs FluentValidation before handler, throws `ValidationException` on failure. `LoggingBehavior<TRequest, TResponse>` logs request name + duration via Serilog
3. **Define repository interfaces** — `IQuizRepository`, `ICategoryRepository` in `TechQuiz.Application/Abstractions`. Methods needed for use cases only — don't over-design
4. **Define IUserContext** — abstraction for "who is the current user". Returns `UserId` from JWT claims. Implemented in Infrastructure later
5. **Define IUnitOfWork** — `Task<int> SaveChangesAsync(CancellationToken)`. Implemented in Infrastructure via EF Core later
6. **DTOs** — `CategoryDto`, `QuestionDto` (without IsCorrect on options!), `QuizSessionDto`, `AnswerDto`, `QuizResultDto` with score + per-question breakdown
7. **GetCategoriesQuery handler** — write failing test first: returns categories with progress%. Implement against mock `ICategoryRepository`
8. **StartQuizCommand handler** — validation: category exists, has questions. Creates QuizAttempt, returns first batch of questions
9. **SubmitAnswerCommand handler** — validation: attempt exists, belongs to current user, not completed, question belongs to attempt's quiz. Persists answer
10. **CompleteQuizCommand handler** — marks attempt completed, computes Score via Domain logic, returns ResultDto
11. **GetAttemptHistoryQuery handler** — returns paginated list of attempts for current user, ordered by date desc
12. **All handler tests** — mock repositories with NSubstitute, assert behavior + edge cases (unauthorized access, completed attempt, missing data)

## Notes
Don't implement repositories yet — that's Iteration 1.3. All Application tests run against mocks. This separation is the **whole point** of Clean Architecture: Application logic provable without a database.
