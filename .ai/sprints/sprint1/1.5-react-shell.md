# Iteration 1.5 — React shell + auth UI

> Phase 1 · Status: planned

## Goal
React app boots in dev, talks to API, handles login/register/logout, manages JWT in memory + refresh in HttpOnly cookie, renders the topbar shell with theme toggle.

## Definition of Done
- [ ] Vite dev server runs alongside API in `docker compose up`
- [ ] Tailwind configured with design tokens from `docs/ARCHITECTURE.md` (Visual Design System)
- [ ] Both dark and light themes work; toggle persists to localStorage; respects `prefers-color-scheme` on first visit
- [ ] React Router v6 with protected routes via `<RequireAuth>` wrapper
- [ ] Auth context provides `user`, `login()`, `logout()`, `register()`
- [ ] JWT stored in memory only; refresh token in HttpOnly cookie set by API
- [ ] Login page matches `mockups/login-dark.html` and `mockups/login-light.html`
- [ ] Topbar shell renders on all authenticated routes; hidden on `/quiz/:id`
- [ ] Logout clears state and redirects to login
- [ ] React Query installed and configured with sensible defaults (stale time, retry policy)

## Tasks (in order)

1. **Tailwind config** — `tailwind.config.js` extends theme with custom violet shades, slate scale, Geist + JetBrains Mono fonts. CSS variables defined in `index.css` for `--bg-base`, `--bg-surface`, `--accent`, etc.
2. **Theme context** — `ThemeProvider` reads localStorage / `prefers-color-scheme`, sets `data-theme="dark|light"` on `<html>`. Toggle button changes attribute, persists choice
3. **API client** — `axios` instance with `baseURL` from env var, request interceptor adds JWT, response interceptor catches 401 → tries refresh once → retries original request → on refresh failure, force logout
4. **AuthContext** — `useAuth()` hook returns user + actions. Login calls `/api/auth/login`, stores JWT in memory (React state), API sets refresh cookie. On app boot, attempt refresh; if it succeeds, user stays logged in
5. **React Router setup** — routes: `/login`, `/register`, `/categories`, `/quiz/:id`, `/result/:attemptId`. `<RequireAuth>` redirects unauthenticated to `/login`
6. **Shell component** — `<AppShell>` wraps authenticated routes with topbar. Topbar: logo (left), nav links (center, some with "soon" badges per ADR-014), theme toggle + avatar (right). `<AppShell>` checks `useLocation()` and renders only the `<Outlet />` (no header) when route is `/quiz/:id`
7. **Login page** — exact match to mockup: split screen, left form (email + password + login button), right gradient mesh with hero tile + supporting stack. "Continue as demo" button calls login with demo credentials. Validation via `react-hook-form` + zod
8. **Register page** — variant of login: email + password + confirm password. Same visual frame
9. **Loading states** — full-page spinner during auth bootstrap; button loading state during login/register submission
10. **Error display** — failed login shows inline error below form. Use toast (sonner library) for unexpected errors

## Notes
The JWT-in-memory + refresh-in-cookie pattern requires the API to set the cookie with `SameSite=Strict; HttpOnly; Secure` (Secure relaxed for dev). If you skip this iteration's auth security model and store JWT in localStorage, you're vulnerable to XSS. Don't.

Demo button: this is your **most useful feature for portfolio**. Recruiter clicks demo, lands in a populated app instantly. Treat it as a first-class UX feature, not a hack.
