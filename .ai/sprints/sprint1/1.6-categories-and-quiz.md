# Iteration 1.6 — Categories + Quiz flow

> Phase 1 · Status: done (session C — keyboard, answer persistence, exit modal, complete→result)

## Goal
User can navigate from Categories → select a category → step through a full quiz → submit. Quiz UI is keyboard-driven, full-screen, with progress and exit handling.

## Definition of Done
- [x] Categories page matches `mockups/categories-*.html` with all 10 cards (2 active, 8 "Coming soon")
- [x] Click on active category → navigates to `/quiz/:id` after starting quiz via API
- [x] Quiz page matches `mockups/quiz-multiple-choice-*.html`: full-screen mode, mini-header with progress bar + exit X, centered question, 4 options with keyboard shortcuts 1-4
- [x] Keyboard handling: 1-4 selects option, Enter advances, Esc opens exit modal
- [x] Exit modal: "Are you sure?" with Cancel + "Yes, exit" buttons (exiting forfeits the attempt)
- [x] Selected state visually shows three changes per ADR-015 (violet border, filled prefix, outer glow)
- [x] Answers persist to API as user navigates between questions
- [x] Next button disabled until an answer is selected (or allow skip — implement as per ADR-015 "answer can be changed before clicking Next")
- [x] Last question's "Next" button labeled "Submit quiz" — calls Complete and navigates to Result

## Tasks (in order)

1. **CategoriesPage** — `useQuery(['categories'])` fetches list. Render 3-column grid. Active categories link to `/quiz/start?categoryId=X`, disabled cards have no link and show "Coming soon" badge. Match mockup styling exactly
2. **Quiz starter route** — `/quiz/start?categoryId=X` is a transient route: calls `POST /api/quizzes/start`, gets back `attemptId` + questions, navigates to `/quiz/:attemptId` with state in router (or React Query cache)
3. **QuizPage** — reads `attemptId` from params, retrieves questions from query cache or refetches. Local state: `currentIndex`, `answers` (Map<questionId, optionId>)
4. **Mini-header component** — category name + "3 of 10" counter, progress bar (animated `transition: width 0.3s`), exit X button. Hidden styling for shell handled by `<AppShell>` route check from 1.5
5. **Question component** — renders one question: difficulty badge, question text, 4 options with monospace number prefixes (1-4). `onClick` selects answer
6. **Selected state styles** — violet border, filled prefix square (white text on violet bg), 3px outer glow via `box-shadow: 0 0 0 3px rgba(139,92,246,0.15)`. All three apply simultaneously
7. **Keyboard handler** — `useEffect` registers global keydown listener: 1-4 selects option at that index, Enter advances if answer selected, Esc opens exit modal. Clean up on unmount
8. **Answer submission** — on selecting an option, optimistically update local state + fire `POST /api/quizzes/{id}/answer` (debounced/idempotent in case user changes answer multiple times before advancing)
9. **Exit modal** — radix-ui Dialog component or shadcn equivalent. "Are you sure you want to exit? Your progress will be lost." with confirm/cancel. On confirm, navigate to `/categories` without calling Complete
10. **Submit quiz** — on last question's "Submit", call `POST /api/quizzes/{id}/complete`, navigate to `/result/:attemptId`

## Notes
This iteration has the **most UX polish**. Mockups define the look; this iteration brings the interactions. Test keyboard shortcuts manually — they should feel snappy, not laggy. If selecting option `1` then immediately pressing `Enter` doesn't advance reliably, batch state updates correctly.

Code question UI from `mockups/quiz-code-output-*.html` is **forward-look only** for Phase 3 — don't implement it yet. MVP is multiple choice only.

**Known MVP limitation (session A → resolve in session B):** the quiz session is cached in memory only — `useStartQuiz` seeds it via `setQueryData(quizSessionKey(...))` with no `queryFn` behind the key, and the API exposes no `GET` for an in-progress attempt's (answer-free) questions. A hard refresh or deep-link onto `/quiz/:attemptId` therefore has no data to render. Session B's QuizPage must detect the cache miss and redirect to `/categories` (the cheap, pragmatic fix). A proper resume flow — `GET /api/quizzes/{attemptId}/questions` returning a `QuestionDto` projection without `IsCorrect` — is deferred to a later iteration (attempt resume / history).
