## Tasks (in order)

1. **Provision Azure resources** — via Azure Portal or `az` CLI: Resource Group `techquiz-staging`, App Service Plan `techquiz-plan-staging` (Linux, B1 or F1 free), App Services `techquiz-api-staging` + `techquiz-web-staging`, PostgreSQL Flexible Server `techquiz-db-staging`
2. **Create Azure AD service principal** — `az ad sp create-for-rbac --name "techquiz-github-actions" --role contributor --scopes /subscriptions/{sub-id}/resourceGroups/techquiz-staging --sdk-auth`. Output JSON → GitHub secret `AZURE_CREDENTIALS`
3. **Configure App Service environment variables** — In Azure Portal, set on both App Services: `ASPNETCORE_ENVIRONMENT=Staging`, `ConnectionStrings__DefaultConnection=...` (from PostgreSQL connection details), JWT signing key
4. **Configure App Service for .NET 9** — Linux App Service runtime: `.NET 9 (LTS)`. Startup command default (Kestrel binds 8080 inside container, App Service maps to public 443)
5. **Configure App Service for static web (Vite build)** — Linux App Service with `node:20-lts` runtime, custom startup command: `pm2 serve /home/site/wwwroot 8080 --spa`
6. **Database setup** — Create database `techquiz` in PostgreSQL Flexible Server. Configure firewall to allow Azure services. Grab connection string → GitHub secret `STAGING_DB_CONNECTION`
7. **Application Insights setup (optional but recommended)** — Create AI resource, connect both App Services, add instrumentation key to Serilog config for production logging
8. **First deploy via manual dispatch** — `gh workflow run deploy-staging.yml` from local machine, watch GitHub Actions log, troubleshoot any issues
9. **Smoke test deployed app** — Register a fresh user via the live UI, complete a full quiz, verify Result screen renders, verify data persisted in staging DB
10. **README badge + link** — Add live URL to top of README with a deploy status badge: `![Deploy status](https://github.com/{owner}/techquiz/actions/workflows/deploy-staging.yml/badge.svg)`
11. **Custom domain (if owned)** — Configure `app.techquiz.dev` → `techquiz-web-staging.azurewebsites.net` via CNAME, enable App Service custom domain + free SSL via App Service Managed Certificates

## Notes
**This iteration is what turns the portfolio piece from "code you can read" into "app you can try".** Single biggest leverage move in the whole MVP.

Be ready for **Azure-specific friction**:
- First deploy will probably fail. Read logs, fix env vars, retry.
- F1 free tier App Service has no Always On — first request after sleep takes ~30 seconds. Worth upgrading to B1 (~$13/mo) for portfolio purposes.
- Azure Database for PostgreSQL Flexible Server has no free tier, only Burstable. Cheapest is ~$15/mo. Alternative: use a free Neon or Supabase database for staging, point connection string there instead.

Cost optimization (if portfolio budget is tight):
- App Service: F1 free tier (with cold start tolerance) → $0
- PostgreSQL: external free tier from Neon (https://neon.tech, free Postgres 16) → $0
- Total: $0/month, with the trade-off of slower cold starts and external DB
