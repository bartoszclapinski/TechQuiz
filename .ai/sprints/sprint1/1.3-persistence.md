## Tasks (in order)

1. **Create AppDbContext** — inherits `IdentityDbContext<IdentityUser>`. Add `DbSet<Category>`, `DbSet<Question>`, `DbSet<Option>`, `DbSet<Quiz>`, `DbSet<QuizAttempt>`, `DbSet<Answer>`
2. **Entity configurations** — separate `IEntityTypeConfiguration<T>` per entity. Define keys, indexes (CategoryId on Question, UserId on QuizAttempt), foreign keys, cascade behaviors. PostgreSQL conventions: `snake_case` column naming via extension method on ModelBuilder
3. **Initial migration** — `dotnet ef migrations add InitialCreate -p TechQuiz.Infrastructure -s TechQuiz.Api`. Inspect generated SQL, ensure no surprises
4. **Repository implementations** — `QuizRepository : IQuizRepository`, `CategoryRepository : ICategoryRepository`. Use `Include()` only where actually needed, avoid N+1
5. **UserContext implementation** — `HttpUserContext : IUserContext`, reads `UserId` claim from `IHttpContextAccessor.HttpContext.User`
6. **UnitOfWork implementation** — wraps `AppDbContext.SaveChangesAsync`. Could be just delegated to DbContext but the abstraction keeps Application clean
7. **DI registration** — `Infrastructure/DependencyInjection.cs` registers DbContext, repositories, UserContext, UnitOfWork. Called from `Program.cs` in Api
8. **Seed data** — `Infrastructure/Persistence/Seed/DataSeeder.cs`. Demo user `demo@techquiz.local` / `Demo123!` with confirmed email. Categories: "C# Basics" and "ASP.NET Core" with 15-18 hardcoded questions each. Difficulty mix: ~5 Easy / 7 Medium / 3 Hard per category. Run seed at startup only if categories table is empty
9. **Integration tests setup** — `Infrastructure.Tests` uses `Testcontainers.PostgreSql`. Base class `IntegrationTestBase` spins up container per test class, applies migrations, seeds. Tests use real DbContext
10. **Integration tests for repositories** — round-trip tests: save Quiz, retrieve, assert equality. Validate cascade deletes. Validate indexes used (via `EXPLAIN` if curious)
