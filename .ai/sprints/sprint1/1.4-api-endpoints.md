## Tasks (in order)

1. **AuthController** — register hashes password via Identity, login returns JWT + refresh token, refresh exchanges refresh token for new JWT. Refresh tokens stored in DB (separate table `refresh_tokens`)
2. **CategoriesController** — `GET /api/categories` calls `GetCategoriesQuery`, returns `List<CategoryDto>`. Authorized
3. **QuizzesController** — five actions matching the use cases from 1.2. Each action is a thin wrapper: extract route/body, send MediatR command, return result
4. **AttemptsController** — `GET /api/attempts?page=1&pageSize=20` for history
5. **Global exception middleware** — `ExceptionHandlingMiddleware` catches `ValidationException` → 400 with field errors, `DomainException` → 422 with message, `UnauthorizedAccessException` → 403, fallback → 500 with generic message. All responses follow RFC 7807 ProblemDetails
6. **Swagger setup** — `Swashbuckle.AspNetCore` already installed; add JWT bearer config so "Authorize" button works. Add XML doc comments on all action methods, enable XML doc generation in csproj
7. **CORS policy** — for dev, allow `http://localhost:5173` (Vite default). Production CORS comes in Phase 4 (deployment)
8. **API integration tests** — `WebApplicationFactory<Program>` based, runs against Testcontainers Postgres. Tests cover happy paths + auth required + validation errors
9. **Postman collection** — manually built or exported from a working session. Includes environment variables for `{{baseUrl}}` and `{{token}}`. Pre-request scripts set token automatically after login. Newman-runnable for CI integration later
10. **Update Swagger description** — add API title "TechQuiz API", contact info, version `1.0.0-mvp`

### Session A (auth) — review follow-up
The 1.4-A code review (PR #62) raised six points. Three were fixed in-branch:
- Refresh tokens are now hashed at rest — SHA-256, stored in `token_hash`, raw value returned to the client only (#65).
- Login email claim derives from the canonical stored email, matching refresh (#64).
- `RefreshToken` uses private setters so the `Issue` factory is the only construction path (#63).

Three are **consciously deferred** as MVP debt, tracked as issues:
- **#66 — reuse detection (family revocation).** Reusing a revoked token returns 401 but does not revoke the user's whole token family. Theft-case hardening; rotation + single-use already hold.
- **#67 — rotation race.** Concurrent `/refresh` with the same token can mint two families; needs a RowVersion/xmin concurrency token. Low likelihood for a portfolio app.
- **#68 — cleanup job.** `refresh_tokens` grows unbounded; needs a prune job for expired/revoked rows.

### Session C (API polish — errors, Scalar, CORS)
- **`ForbiddenAccessException` split from auth 401 (#77).** The quiz ownership guards (submit/complete/result) threw `UnauthorizedAccessException` — the same type auth failures use. Failed authentication is 401; acting on someone else's resource is 403. Introduced `ForbiddenAccessException` (Application layer) so the global handler maps the two cleanly. Tests updated (TDD).
- **Global `IExceptionHandler` → ProblemDetails (#78).** `GlobalExceptionHandler` + `AddProblemDetails` + `UseExceptionHandler`. RFC 7807 responses with `type`/`title`/`status`/`detail`/`traceId`; validation adds a per-field `errors` map. Mapping: `ValidationException`/`RegistrationFailedException`/`ArgumentException` → 400, `UnauthorizedAccessException` → 401, `ForbiddenAccessException` → 403, `KeyNotFoundException` → 404, `DomainException` → 409, fallback → 500 (generic message, no stack trace leaked).
- **Scalar OpenAPI UI (#79).** Swashbuckle was never installed — the project uses the built-in `Microsoft.AspNetCore.OpenApi`. Added `Scalar.AspNetCore` (new dependency) at `/scalar/v1` (Development), plus a `BearerSecuritySchemeTransformer` (`IOpenApiDocumentTransformer`) so the **Authorize** button injects the JWT.
- **CORS for the Vite dev origin (#80).** Named policy `web` allowing `http://localhost:5173` with `AllowCredentials` (refresh cookie); explicit origin because credentials rule out `AllowAnyOrigin`. Production CORS is a Phase 4 concern.

Verified live on the docker stack: error paths return 401/401/400/404/409 with ProblemDetails bodies; Scalar UI loads and the OpenAPI doc carries the Bearer scheme; CORS preflight from `localhost:5173` returns 204 with the allow-origin/credentials headers, while a disallowed origin gets none.

**DoD note:** XML doc comments on actions (originally listed under the Swagger task) are not done — Scalar renders the endpoints without them. Tracked as nice-to-have, not blocking the MVP API milestone.

### Session D (integration tests + Newman/CI smoke runner)
Closes out the iteration: the two items deferred from sessions B/C are now in place.

- **`WebApplicationFactory<Program>` harness + health smoke (#83).** New `TechQuiz.Api.Tests` project (`Microsoft.NET.Sdk.Web`) booting the real host against a Testcontainers `postgres:16-alpine` instance, shared across the run via an xUnit collection fixture. `Program.cs` exposes `public partial class Program;` so the factory can reference it. Two ordering gotchas solved: (1) the host's startup seeder does **not** apply migrations, so the factory migrates a standalone `AppDbContext` before the host boots; (2) `WebApplicationFactory` drives minimal hosting through a `DeferredHostBuilder`, so `AddInMemoryCollection` config overrides get re-overridden by the app's own appsettings — overrides are pushed through process **environment variables** (`ConnectionStrings__DefaultConnection`, `Jwt__SigningKey`) instead, which win over both appsettings and user-secrets.
- **Integration coverage for auth, authorization, quiz flow (#84).** `AuthorizationTests` (401 without a token on `/api/categories` + `/api/attempts`, 200 with the demo token), `AuthEndpointsTests` (register with an invalid payload → 400 `application/problem+json` with per-field `errors` for `Email`/`Password`), and `QuizFlowTests` (full E2E: login → categories → start, asserting **no `iscorrect` leak** per Hard Rule #4 → answer each question → complete → re-fetch result). The existing CI `backend` job (`dotnet test TechQuiz.sln`) picks these up automatically — Testcontainers runs on `ubuntu-latest`, so no CI change was needed for the tests themselves.
- **Newman/CI smoke runner (#85).** `docs/postman/package.json` adds a `npm run smoke` script (`newman run` the committed collection + local environment). `.github/workflows/api-smoke.yml` runs the identical command on `workflow_dispatch` against a freshly booted API (build → apply migrations with `ASPNETCORE_ENVIRONMENT=Production` to keep the dev seeder off, since there is no design-time factory → start with `Development` to seed demo data → wait for `/health` → `npm ci` + `npm run smoke`). Kept manual, not a per-PR gate, because the in-process `WebApplicationFactory` E2E already covers the flow; the workflow's value is exercising the real HTTP stack with the same collection developers run by hand.

Verified live: all six integration tests green against Testcontainers Postgres, and `npm run smoke` green against the docker stack (9 requests, 0 failures). **This completes iteration 1.4 — the MVP backend milestone.**
