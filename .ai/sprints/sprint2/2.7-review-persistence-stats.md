# Iteration 2.7 — Review persistence + spaced-repetition feedback + stats

> Phase 2 · Status: planned

## Goal
Make the daily review **stateful**. Today (after 2.6) grading is a pure function and nothing is saved,
so a completed review leaves no trace and doesn't change the queue — the same questions resurface
forever. This iteration:
- **persists** each completed review as a `ReviewSession` (its own table, **not** a `QuizAttempt`),
- **feeds review outcomes back into the spaced-repetition queue** (a question answered correctly in a
  review drops out of the next queue; answered wrong, it returns) — the "full SR" the owner asked for,
- **gates** the Dashboard banner on **done-today**,
- gives review its **own stats** (sessions, questions reviewed, review accuracy, current + best review
  **streak**) as a Dashboard tile — review has fewer questions, so it earns its own numbers.

Milestones / achievement badges for review streaks are **out** — they are iteration **2.8**.

`ADR-021` records the reversal of 2.6 decision (a) ("stateless, no persistence").

## Scope
- **In:**
  - **Domain (TDD):** `ReviewSession` aggregate — `{ Id, UserId, CompletedAt, Items: [{ QuestionId,
    SelectedOptionId?, AnsweredAt }] }`. Correctness is **derived** at read time (match the chosen
    option's `IsCorrect`), consistent with the 2.5 "derive, don't persist correctness" decision.
    Extract a pure `StreakCalculator.CurrentStreak(activeDays, today)` (consecutive UTC days, one-day
    grace) from the Dashboard handler and **reuse it for both** the quiz streak and the new review
    streak (duplication now justifies extraction).
  - **Application (TDD):** `GradeReviewCommand` handler now **persists** a `ReviewSession` before
    returning the per-question results (it becomes a write). New `GetReviewStatsQuery` + handler +
    `ReviewStatsDto { TotalSessions, TotalQuestionsReviewed, AccuracyPercentage?, CurrentStreakDays,
    BestStreakDays }`. `IQuizRepository` (or a new `IReviewRepository` — see decision (g)) gains
    `AddReviewSessionAsync`, a read for stats, and the **extended candidate source**.
  - **Spaced-repetition feedback (the elegant part):** the existing 2.5 selector
    (`ReviewSelector` — "latest answer per question, keep only those last answered wrong") stays
    untouched. We only **union review answers into the candidate source**: `GetReviewCandidatesAsync`
    returns one candidate per answer from quiz attempts **and** review sessions. A correct review
    answer then becomes the question's latest answer → it drops from the queue; a wrong one keeps it.
  - **Infrastructure:** EF mapping for `ReviewSession` + owned `Items`, an **EF migration** (new
    table — first schema change since the review feature began), repository implementations, and the
    unioned candidate query. Testcontainers tests.
  - **Api:** `GET /api/review/stats` (`[Authorize]`, scoped to the user). `POST /api/review/grade`
    keeps its contract but now writes a session as a side effect.
  - **Frontend:** a **review stats tile** on the Dashboard (sessions, accuracy, review streak);
    **done-today** state on the daily banner ("Reviewed today ✓ X/Y" + a "Review again" affordance vs.
    the count); `use-review-stats` hook; after grading, **invalidate** `['review','daily']` and
    `['review','stats']` so the banner/tile reflect the just-completed session.
  - **ADR-021** — reviews persist to their own table and feed the SR queue; supersedes 2.6 decision (a).
- **Decisions:**
  - **(a) Persist to a dedicated `ReviewSession` table, never `QuizAttempt`.** Keeps the spirit of 2.6
    decision (a) — quiz History/Dashboard aggregates stay clean — while reversing only the
    "stateless / don't persist" part. Recorded as ADR-021 (hard rule #5).
  - **(b) Full SR via candidate-source union, not a selector rewrite.** Review outcomes flow through the
    same `ReviewSelector` by joining review answers into `GetReviewCandidatesAsync`. Minimal, and it
    reuses the proven 2.5 weighting/ordering.
  - **(c) Derive correctness on read.** Store `SelectedOptionId` + `AnsweredAt`; compute `WasCorrect`
    by matching `Option.IsCorrect`, exactly like quiz scoring and 2.5's candidate read.
  - **(d) Review streak = consecutive UTC days with ≥1 completed `ReviewSession`,** same one-day grace
    as the quiz streak (no activity *today* doesn't break the run; it resets only after a full empty
    day). Shared `StreakCalculator` guarantees parity.
  - **(e) Done-today = a `ReviewSession` exists with `CompletedAt` on today's UTC date.** Matches the
    streak/Dashboard UTC-day convention.
  - **(f) Grade becomes a mutation that writes.** Frontend treats it as such and invalidates the daily
    queue + stats queries on success.
  - **(g) Repository seam:** add the review reads/writes to the existing `IQuizRepository` for now
    (review already lives there since 2.5), rather than splitting an `IReviewRepository` — avoid a
    premature interface split; revisit if the review surface keeps growing.
  - **(h) Hard rule #4 still holds.** `GET /api/review/daily` keeps omitting correctness; it is revealed
    only by `/grade` after submit. Persistence doesn't change what the active-review payload exposes.
- **Out:**
  - **Milestones / achievement badges** for review streaks/counts → **iteration 2.8**.
  - Per-question SM-2 ease factors / explicit interval scheduling beyond the existing recency-weighted
    selector. The union delivers the feedback loop; finer scheduling is a later concern.
  - Backfilling historical reviews (none were persisted before this iteration).
  - Crediting reviews toward the **quiz** streak or quiz Dashboard stats (review has its *own* streak).

## Definition of Done
- [ ] `POST /api/review/grade` persists a `ReviewSession` (+ items) for the user, then returns the same
      per-question results as before; `[Authorize]`; no `QuizAttempt` created.
- [ ] EF migration adds the `ReviewSession` table and applies cleanly; quiz History/Dashboard aggregates
      are unchanged (no review rows leak into quiz queries).
- [ ] **SR feedback proven:** an integration test shows a question answered *correctly* in a review drops
      out of the next daily queue, and one answered *wrong* stays/returns.
- [ ] `GET /api/review/stats` returns total sessions, questions reviewed, review accuracy, and current +
      best review streak; `[Authorize]`, user-scoped.
- [ ] Dashboard shows a **review stats tile** and the daily banner shows a **done-today** state after a
      completed review; CTA still enters `/review`. Both themes verified.
- [ ] Shared `StreakCalculator` used by both quiz and review streaks; existing Dashboard streak tests
      still green.
- [ ] Full .NET suite green; `pnpm build` + lint clean.
- [ ] `ADR-021` appended; 2.6 decision (a) noted as superseded.
- [ ] Manual verification in `LOG.md`: stack up (rebuild api + web), demo login → Dashboard shows review
      stats + count → run + submit a review → banner flips to "done today", a correctly-answered question
      no longer appears in a fresh queue, stats tile updates. Owner click-through confirms.
