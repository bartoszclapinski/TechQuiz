# Iteration 2.2 — Dashboard UI

> Phase 2 · Status: done

## Goal
Build the **Dashboard screen** — the 8-tile bento grid from `mockups/dashboard-*.html` — consuming the
`GET /api/dashboard` contract shipped in 2.1. This is the single most visually impressive screen in the
portfolio (ADR-016), so it gets real charts and a polished empty state, in **both themes**. Promote the
"Dashboard" nav item from its disabled "soon" state to a live route.

## Scope (decided with owner)
- **In:**
  - `features/dashboard/` feature folder: `api.ts` (type + fetch mirroring `DashboardSummaryDto`),
    `use-dashboard.ts` (TanStack **query**), `dashboard-page.tsx` (the grid), tile components.
  - **8 tiles** per the mockup, in a 3-column bento grid:
    1. **Current streak** (1×1) — big number + inline SVG sparkline (14-day activity).
    2. **Score over time** (span 2) — Recharts line chart from `scoreOverTime`.
    3. **Category strength** (row span 2) — Recharts radar from `categoryStrength`.
    4. **Questions answered** (stat) — `totalQuestionsAnswered`.
    5. **Average score** (stat) — `averageScore`.
    6. **Recent activity** (span 2) — list from `recentActivity` (category, score, date).
    7. **Best category** (stat) — **max** of `categoryStrength` (client-derived).
    8. **Needs practice** (stat) — **min** of `categoryStrength` (client-derived).
  - **Empty state** per `dashboard-empty-state.html`: when `averageScore` is null (no completed
    attempts), render the first-run prompt instead of empty charts.
  - **Route + nav:** add `/dashboard` route; move `Dashboard` out of `COMING_SOON` into an active
    `NavLink` in `app-shell.tsx`. Loading + error states for the page.
  - **Both themes** verified (dark/light) using existing CSS-variable tokens — no hardcoded mockup hex.
- **Deferred:**
  - **Time-range filter** (Week/Month/All) → 2.3. Dashboard shows all-time only for now.
  - **History page** → 2.4. "Recent activity" here is the last few; the full list is 2.4.
  - **Daily review tile** → 2.6. Streak/sparkline ship now; the review queue card comes later.

## New dependency — Recharts (hard rule #6)
The line + radar charts justify adding **Recharts** (already named in the stack table + sprint outline
as the Phase-2 charting lib). The sparkline stays **inline SVG** (no dep) — it's a single sub-100px
path, cheaper hand-rolled than via a chart lib. Recharts is called out in the PR description per hard
rule #6.

## Code-block / dark-region note
Code regions stay dark in light mode (ADR-016, known gotcha) — but the Dashboard has no code blocks,
so this doesn't apply here. Charts and tiles follow the **theme**, light in light mode.

## Notes
- **Owner is learning React** — explain why the Dashboard is a TanStack **query** (a cached read keyed
  by user) versus the Run/Submit/Feedback **mutations** in code-challenges, and how Recharts'
  `ResponsiveContainer` handles the grid cells' fluid widths, in the PR/conversation.
- **Match the mockups precisely** (soft rule #6) — adapt for responsive breakpoints (the 3-col grid
  collapses on narrow viewports) but don't redesign the tile set or hierarchy.
- **One query, all tiles** — the page issues a single `useDashboard()` and fans the payload out to the
  tiles; don't add per-tile fetches. This is exactly why 2.1 returns one aggregate.
