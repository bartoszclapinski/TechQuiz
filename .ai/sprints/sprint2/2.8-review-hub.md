# Iteration 2.8 — Review hub page (daily details + session history)

> Phase 2 · Status: done

## Goal
Turn `/review` from "immediately a quiz" into a **hub page for the daily review feature**. After 2.7
the review persists and has stats, but the only way into `/review` drops you straight into the runner,
the post-grade summary lives in component state (lost on navigate — you can't re-open the last result),
and there's no sense of "today is done" on the review screen itself. This iteration:
- makes `/review` a **landing page**: review stats + a **daily section** (start the session, or a
  **done-today** acknowledgement) + a **history list** of past sessions,
- moves the **runner** to its own focused route (`/review/run`), keeping the distraction-free screen,
- adds a **session detail** view (`/review/sessions/:id`) so any past review's graded results are
  re-openable — reusing the 2.6 summary layout,
- adds the backend reads that history needs: **list past sessions** and **read one session's graded
  detail** (per-question correctness derived on read, as everywhere else).

Milestones / achievement badges (the old "2.8") move to **iteration 2.9**.

## Scope
- **In:**
  - **Application (TDD):**
    - `GetReviewSessionsQuery` + handler → `IReadOnlyList<ReviewSessionListItemDto { Id, CompletedAt,
      QuestionCount, CorrectCount }>`, user-scoped, newest first. (2.7's `GetReviewSessionSummariesAsync`
      returned no `Id`; the list needs it to link to detail — extend that read to carry the session id.)
    - `GetReviewSessionDetailQuery(Guid SessionId)` + handler → `ReviewSessionDetailDto { Id, CompletedAt,
      Items: [{ QuestionId, QuestionText, Category, Difficulty, Options:[{Id,Text,OrderIndex}],
      SelectedOptionId?, CorrectOptionId, IsCorrect, Explanation }] }`. **User-scoped**: a session that
      isn't the caller's → `ForbiddenAccessException`; missing → `KeyNotFoundException` (404).
    - `IQuizRepository` gains `GetReviewSessionsAsync(userId)` (list w/ id + counts) and a detail read
      that returns the session's items joined to their questions/options (correctness derived by matching
      `Option.IsCorrect`, never persisted — consistent with 2.5/2.7 decision (c)).
  - **Api:** `GET /api/review/sessions` (list) and `GET /api/review/sessions/{id}` (detail), both
    `[Authorize]`, user-scoped. `/grade`, `/daily`, `/stats` unchanged.
  - **Frontend:**
    - `/review` → **`ReviewHubPage`** (topbar shown): stats header (reuse 2.7 numbers), a **daily card**
      ("N due today → Start review" **or** "Reviewed today ✓" with streak when `reviewedToday`), and a
      **history list** (date · score) linking to detail.
    - `/review/run` → the current runner + post-grade summary flow (full-screen, no topbar). On finish,
      "Back to review" returns to the hub (not the dashboard), and the hub's history/stats reflect the
      just-completed session (grade already invalidates `daily`+`stats`; add `sessions` invalidation).
    - `/review/sessions/:id` → **session detail** reusing the `ReviewSummary` row layout, read from the
      new detail endpoint.
    - `use-review-sessions` (list) + `use-review-session` (detail) hooks; `reviewSessionsKey` /
      `reviewSessionKey(id)` query keys.
    - `AppShell` hides the topbar only on **`/review/run`** and `/quiz/:id` now (the hub + detail keep it).
- **Decisions:**
  - **(a) Runner moves to `/review/run`; `/review` is the hub.** Keeps the focused, topbar-less runner
    (ADR-014) while giving the feature a browsable home. Dashboard's "Start review" CTA now points at
    `/review` (the hub), which is the natural entry; the hub's own button enters `/review/run`.
  - **(b) History detail is a fresh read, not the grade payload.** The post-grade summary stays ephemeral
    (component state); re-opening a past session goes through `GET /api/review/sessions/{id}`. One code
    path for "view a session's results" regardless of age.
  - **(c) Correctness derived on read** for the detail view too — match `SelectedOptionId` to the
    option's `IsCorrect`. No correctness column is ever stored (2.7 decision (c)).
  - **(d) Done-today acknowledgement uses 2.7's `reviewedToday`** (a session with `CompletedAt` on
    today's UTC date). "Done today" means *you completed a session today*, independent of whether
    spaced-repetition returned some questions to the queue — matches 2.7 decision (e).
  - **(e) No new table, no migration.** Everything reads from the `review_sessions` / `review_items`
    tables 2.7 added. Hard rule #4 still holds — detail exposes correctness only for *past, submitted*
    sessions, never for the active `/daily` payload.
- **Out:**
  - **Milestones / achievement badges** → iteration **2.9**.
  - Pagination / infinite scroll on history (session counts are small; a plain list is enough — revisit
    if a user accumulates many sessions).
  - Deleting or replaying a past session.
  - Any change to the spaced-repetition selector or the `/daily` contract.
