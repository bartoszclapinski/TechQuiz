# Iteration 2.3 — Time-range filter (Week / Month / All)

> Phase 2 · Status: done

## Goal
Add the **Week / Month / All time** segmented control to the Dashboard (top-right of the header, per
`mockups/dashboard-*.html`). The selected range filters the Dashboard's aggregations; the backend
folds the range into the existing `GET /api/dashboard` contract (one endpoint, one round-trip — no new
routes), and the frontend caches each range independently.

## Scope (decided with owner)
- **In:**
  - **Backend** — `DashboardRange { Week, Month, All }` enum (Application); `GetDashboardSummaryQuery`
    gains a `Range` parameter; `GET /api/dashboard?range=week|month|all` binds it (**default `All`**
    when the param is absent). The handler filters completed attempts to the range before aggregating.
  - **Range-scoped tiles:** score over time, category strength, questions answered, average score,
    recent activity, best / needs-practice (all computed from the filtered set).
  - **All-time tiles (NOT range-scoped):** **current streak** and the **14-day sparkline** stay
    all-time — they're "state as of now" (consecutive days up to today / a fixed 14-day window), so the
    range filter must not touch them.
  - **Frontend** — `dashboardKey(range)` folds the range into the query key (each range caches
    independently); `fetchDashboardSummary(range)` appends `?range=`; `useDashboard(range)`. A segmented
    control in the header (Week / Month / All time), local `useState`, **default All**.
  - **Both themes** verified.
- **Deferred / out:**
  - **Comparison deltas** (the mockup's "+34 this month", "▲ 4%") — a separate period-over-period
    metric, not a filter. Omitted here as in 2.2.
  - **History page** (2.4) — the full attempt list with its own category filter is separate.

## Window semantics
Date-based, UTC (consistent with streak/sparkline): an attempt is in range when its **completed date**
(`DateOnly`, UTC) is on or after the cutoff.
- **Week** — cutoff `today − 6 days` (a 7-day window including today).
- **Month** — cutoff `today − 29 days` (a 30-day window including today).
- **All** — no cutoff.

## Empty-state interaction (no DTO change)
`averageScore` reflects the **selected range**. The first-run "No data yet" prompt renders only when
`range === 'all' && averageScore === null` — on the All range, filtered == all-time, so a null average
there means the user truly has no completed attempts. A narrower range that filters everything out
(while all-time has data) shows the populated layout with empty charts, not the first-run prompt.

## API binding note
The `range` query param binds to the `DashboardRange` enum by name (case-insensitive). Absent ⇒ the
controller's default `All`. A malformed value yields a 400 (standard model-binding behavior); the
frontend only ever sends `week | month | all`.

## Notes
- **One endpoint, range as a param** — exactly the extension 2.1 anticipated (`query-keys.ts` already
  comments that the range folds into the cache key). Don't add a second route.
- **Why streak/sparkline stay all-time** — they answer "how am I doing *right now*", which a Week/Month
  filter shouldn't rewrite. Keeping them fixed avoids a confusing "streak: 0" when viewing "Week" on a
  Monday morning.
