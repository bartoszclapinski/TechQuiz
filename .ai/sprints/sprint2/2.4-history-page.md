# Iteration 2.4 — History page

> Phase 2 · Status: done

## Goal
A full **History page** — the complete list of the user's past quiz attempts, **filterable by category**
and **sortable by date / score**, with incremental "Load more" paging. Promote the **History** nav item
out of its disabled "soon" state to a live `/history` route. No mockup exists for this screen, so it
follows the existing design system (the Dashboard's Recent-activity rows + the Categories page chrome).

## Scope (decided with owner)
- **In:**
  - **Backend** — a dedicated `GET /api/history` endpoint (completed attempts only), returning a page of
    `HistoryItemDto { AttemptId, Category, ScorePercentage, CompletedAt }`. Query params:
    `category?` (filter), `sortBy` (date|score), `descending` (bool), `page`, `pageSize`.
  - **Repository** — `GetCompletedHistoryPageAsync(userId, category?, sortBy, descending, skip, take)`:
    joins category, filters to completed+scored, optional category filter, server-side sort + paginate.
  - **Application** — `GetHistoryQuery` + handler (thin: compute skip, pass through, map to DTO) +
    validator (page ≥ 1, pageSize 1–100). `HistorySortField { Date, Score }` enum.
  - **Frontend** — `features/history/`: `api.ts`, `query-keys.ts`, `use-history.ts`
    (TanStack **`useInfiniteQuery`**), `history-page.tsx`. Category filter dropdown (from the existing
    categories endpoint), a Date/Score sort control (toggles direction), attempt rows (category, score,
    date) linking to `/result/:attemptId`. "Load more" button; the last page is detected when a page
    returns fewer than `pageSize` items (no total-count round-trip needed).
  - **Route + nav** — add `/history`; move `History` out of `COMING_SOON` to an active `NavLink`.
  - **Both themes** verified; loading / error / empty states.
- **Decisions (owner flagged these as open; locking them here):**
  - **(a) Completed-only.** In-progress attempts have no score and aren't "history". History lists
    completed+scored attempts.
  - **(b) "Load more"** (incremental `useInfiniteQuery`) over numbered pages or infinite scroll —
    simplest, reuses the existing `page` param, and showcases the infinite-query pattern.
  - **(c) Dedicated `/api/history`** rather than extending `/api/attempts`. The generic attempts
    endpoint has distinct, tested semantics (all attempts, desc by StartedAt, no category/score);
    repurposing it would rewrite those tests for no gain. A new endpoint reuses the 2.1 category-join
    projection cleanly and leaves `/api/attempts` intact.
- **Out:**
  - Attempt **detail** view — the existing `/result/:attemptId` screen already covers it; History links
    to it rather than building a new detail page.
  - Multi-category / date-range filters — single category filter only for now.
